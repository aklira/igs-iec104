# C1 — Primitive formats

## Prompt (summarised)

Task C1 of IMPLEMENTATION.md: module `formats` with a bit-level reader and
writer over byte slices; types for UI(n), I16, F16 (normalized, conversions
to and from `f32`), R32 (IEEE 754), BS(n), and the time tags CP56Time2a,
CP24Time2a and CP16Time2a with range-checked constructors. Done when unit
tests cover the minimum and maximum of every field, out-of-range rejection,
and one hand-written byte vector per format derived from the bit layout of
`formats.yaml`.

## Summary

The bit reader, BS(n), I16, F16 and R32 were written in an earlier session.
This session completed the task:

- `crates/igs-iec104-codec/src/formats/times.rs`: CP56Time2a, CP24Time2a and
  CP16Time2a. Each field has a zero-based (first bit, width) constant taken
  from the bit numbers of `formats.yaml`. Constructors check every range.
  Decoders go through the constructors, so an out-of-range wire value is
  rejected. Encoders check the destination length before the first write, so
  a failed encode leaves the buffer unchanged. The flags IV, SU and RES1 are
  set with `with_*` methods, which keeps the constructor arguments within
  clippy's limit.
- `crates/igs-iec104-codec/src/lib.rs`: wires `pub mod formats;`.
- Fixes to code written earlier that did not compile or did not pass its
  own tests:
  - `bs.rs` compared a `u64` with a `u128`; the check now uses `checked_shl`.
  - `floats.rs` had two clippy findings (manual range check and an
    `assert_eq!` on a literal bool).
  - Three tests had wrong expected values: `bits.rs` `within_one_octet`
    and `set_spans_two_octets_and_keeps_other_bits` and `bs.rs`
    `hand_written_vector`. The code was right in all three; the tests
    misread the bit numbering. Their comments now state the bit positions.

Verification: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets --all-features -- -D warnings`, `cargo test --workspace
--all-features` (32 tests in the codec crate, 28 of them new in this task
or earlier) and `cargo deny check` are all green.

The byte vectors were computed twice: by hand from the bit positions, and
with a separate Python script that uses the bit numbers of `formats.yaml`
directly. Both agree (for example CP56Time2a of 1000 ms, 30 min, 12 h, 15th,
Wednesday, July, year 24, summer time: `E8 03 1E 8C 6F 07 18`).

## Decisions

Recorded in `PROVENANCE.md`:

- D-006: day of week 0 is accepted. The range in `formats.yaml` (1..7) omits
  it, but the 101 text marks 0 as "not used".
- D-007: reserved bits are written as 0 and ignored on decoding. The standard
  is silent on the receiver's behaviour.

Also: the RES1 bit of the time tags is named `substituted`, after the GEN
meaning given in 101 §7.2.6.18.

## Points for the reviewer

- The change is larger than the 400-line guideline (about 1 060 added lines
  in the codec crate, most of them the `formats` module and its tests). It
  was not split: the earlier files only compile together with `times` and
  the `lib.rs` wiring.
- CP24Time2a is implemented although the 104 profile forbids it, because the
  101 link layer uses it.
- Day of month is checked against 1..=31 only; the month length is not
  checked, as the task asks for ranges per field.
