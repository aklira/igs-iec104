# F4 — Interop bench skeleton

## Gate

A maintainer approved the reference peer image
`ghcr.io/aklira/fledgepower/fledge:v1.2.3`
(`sha256:9191e191572d26d8c3ad197e2362f706873f87e609637ce6994bc17766b9404e`).
It contains FledgePower with the IEC 104 south plugin (client role) and the
IEC 104 north plugin (server role). Both plugins are built on a third-party
IEC 104 stack. The image is used as a black box only: it runs as a separate
container and only its REST API and network traffic are observed.

## Prompt (summarised)

Task F4 of IMPLEMENTATION.md: create `bench/` with `pyproject.toml`
(pytest), a `docker-compose.yml` running the reference peer in its own
container, a capture helper (tcpdump), an assertion helper based on
`tshark -T json`, and a README. Done when one scenario connects to the
reference server, sends STARTDT and a general interrogation with an existing
tool, and the capture decodes in tshark without errors.

## Summary

- `bench/docker-compose.yml`: `ref-server` and `ref-client` both run the
  approved image, pinned by digest, on 172.31.104.0/24. `capture` (netshoot,
  pinned by its multi-arch index digest) shares the server's network
  namespace and runs tcpdump on port 2404.
- `bench/peer/bootstrap.sh`: replaces the image's start script, which exits
  on Fledge 3.1 because its module import calls `GET/PUT
  /fledge/service/<name>` and Fledge answers 405. The bootstrap starts
  Fledge, creates one service from a JSON definition with its config in the
  same `POST /fledge/service` call, and writes `/tmp/bench-ready` once the
  service is running.
- `bench/peer/server.json` and `client.json`: the plugin configurations. The
  server keeps the plugin's default catch-all redundancy group, so it accepts
  any client and does not need a south connection. The client points at the
  server and interrogates at start-up. Both declare two points under common
  address 45.
- `bench/igs_bench/`: compose wrapper (docker compose or podman-compose,
  override with `BENCH_COMPOSE`), capture stop, and tshark helpers. The
  tshark helpers decode with `-T json -e ...`, flag malformed frames or
  error-level expert info, and match frames by source, Info label, type ID
  and cause.
- `bench/tests/test_f4_reference_gi.py`: the done criterion. U-format
  functions are matched on tshark's own labels, so no APCI bit values are
  written from memory. Type ID 100 and causes 6, 7 and 10 come from
  `docs/spec/104/data/type_ids.yaml` and the profile.

Verification: `python3 -m pytest` in `bench/` passed in 72 s with Podman
5.7.0 and podman-compose 1.5.0 on WSL2. The capture shows STARTDT act/con,
C_IC_NA_1 activation to the broadcast address, then activation
confirmation, the two interrogated points and activation termination from
common address 45. tshark reports no malformed frame and no error-level
expert info.

Points for the reviewer:

- The image's `start.sh` / `importModules.sh` fails on a fresh container
  (405 described above). The bench does not depend on it, but the image
  itself needs fixing if it is used outside the bench.
- The bench is not run in CI: GitHub runners have Docker, but the
  approved image must stay reachable there and a full run takes over a
  minute. To be decided with L4.
