# S4 — `igs104-server` binary

## Prompt (summarised)

Task S4 of IMPLEMENTATION.md: a configurable demo server, with its points read from a TOML file and
simulated value changes. Done when it is documented and usable as the bench device under test. Depends on
S2. The maintainer asked for it with "commence S4"; the work stays in the working tree until a commit is
requested.

## Status

**Done in the working tree.** The points come from a TOML file, given with `--points`, as the plan asks.
The box for S4 in IMPLEMENTATION.md §6 is ticked in the commit that adds the file reader.

## Approval

The maintainer approved `toml` and `serde` (with its derive feature) for this binary. Both are MIT or
Apache-2.0, and `cargo deny` passes. `toml` 1.x has MSRV 1.85, the workspace floor. They are regular
dependencies of the crate, not of the binary alone: a bin-only dependency would need a feature gate,
and the library is small enough to carry them for now.

## Summary

- `crates/igs-iec104/src/bin/igs104_server.rs`: the binary. Options: `--bind` (default `0.0.0.0:2404`),
  `-c` common address (1 to 65534; the global address is refused), `--for SECONDS`. It registers the points,
  starts their simulations, and serves the station until the process stops or `--for` ends.
- `crates/igs-iec104/src/bin/igs104_server/points.rs`: the point model. A point has an address, a type
  (single, double, normalized, scaled, float, counter), a time tag, a group, a command flag and a
  simulation (constant, toggle, ramp, count). `validate` checks the points before the station starts;
  `value` gives the value after a number of steps, so a run is repeatable.
- `crates/igs-iec104/src/bin/igs104_server/handler.rs`: the application. It accepts the selects and the
  executions of the points that take commands, and prints them. Any other address is refused with cause 47.
- `docs/igs104-server.md`: how to run it, what it answers, and its demo points. The README links to it.
- Tests: 9 unit tests of the model and the handler; 4 end-to-end tests that run the binary as a process and
  drive it with the client library (interrogation, command, simulated change, `--for`). The interrogation test
  checks the documented type of a time-tagged point.

## Decisions

- **The commands are printed, not applied.** An executed command does not change the value of its point. A
  demo that changed values on commands would need a rule per type, which the task does not ask for.
- **Simulations are functions of the step number.** No random source, so that a run and a bench capture are
  repeatable.
- **A constant point holds its zero value.** There is no initial value in the points model, so a constant
  single point is off.
- **The station is one redundancy group** (S3): the server's connections share its points, one started at a
  time.
- **No limit on the number of points.** The S5 load test (10 000 points) will measure it; the binary has not
  been run with that many points.
- **Validation refuses address 0, out-of-range and duplicate addresses, a simulation that does not fit the
  type, a zero period, a group outside 1 to 16, and a command on a counter.**

## Second increment: the points file

- `crates/igs-iec104/src/bin/igs104_server/points.rs`: `parse` reads a TOML file of `[[point]]` tables
  with serde (`deny_unknown_fields`, so a misspelt key is an error). Each simulation names its numbers:
  `toggle` needs `period_ms`, `ramp` needs `period_ms` and `increment` (32-bit), `count` needs `period_ms`
  and `increment` (0 to 2^32-1), and `constant` takes neither. A number that the motion does not use is an
  error. The file must hold at least one point; the points are then checked with the existing `validate`.
- `crates/igs-iec104/src/bin/igs104_server.rs`: the option `-p`, `--points FILE`. Without it, the built-in
  demo set is served, as before.
- `docs/igs104-server.points.toml`: the built-in demo set written as a file. A unit test checks that it
  parses to exactly the built-in set, so the documented example cannot drift from the code.
- `docs/igs104-server.md`: the option, the file format and the rules, and the TLS statement (the station
  has no TLS option).
- `crates/igs-iec104/tests/server_binary.rs`: a test that the station serves only the points of its file.
