## Summary

- **Sources.** The matrix was written from the code: the builders of `procedures.rs`, the methods
  of `Client`, the dispatch of `server/respond.rs` (interrogation, counters, read, clock, test
  command, commands through `operation_of`, refusals), and `PointValue::type_id` for the monitoring
  types. No clause text is quoted.
- **Gaps found, closed with tests.** Three rows had no test of their own:
  - the station's answers to the double, regulating step, scaled and floating set-point commands,
    and to the time-tagged forms of every command (only the single command and the normalized
    set-point were tested): `respond` `every_command_type_is_selected_then_executed` now selects
    and executes each of the twelve command types;
  - the time-tagged forms of the published monitoring types (only M_SP_TB_1 was tested): `image`
    `every_point_type_is_published_in_its_plain_and_time_tagged_forms` builds each plain and
    time-tagged type and validates it against the profile;
  - the client's group interrogation: `procedures`
    `a_group_interrogation_carries_the_qualifier_of_its_group`.
- **Stated limits.** The refusal of the unsupported commands is tested for C_BO_NA_1 only; the
  matrix says that the other types take the same branch. The termination of an execution follows its
  confirmation at once, which the matrix states.
- **Check.** A script checked that every test name in the matrix is a function of the crates.
