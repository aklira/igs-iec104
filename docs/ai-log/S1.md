# S1 — Process image

## Prompt (summarised)

Task S1 of IMPLEMENTATION.md: a typed point database by common address and information object
address, with change detection and an event queue for spontaneous transmission (cause 3), bounded,
with an overflow policy. Depends on C4. Done when unit and property tests pass.

The maintainer asked for this task with "commence S1". Commits happen only on request, so the work
is left in the working tree.

## Summary

`crates/igs-iec104/src/process_image.rs`, with its tests in `process_image/tests.rs`:

- `PointValue`: one variant per monitoring type that carries a point value: single (M_SP), double
  (M_DP), step (M_ST), bitstring (M_BO), normalized (M_ME_NA), scaled (M_ME_NB), float (M_ME_NC),
  counter (M_IT), packed (M_PS) and normalized without quality (M_ME_ND). The quality is part of
  each value. `type_id(stamped)` gives the ASDU type, the time-tagged form when `stamped`, or `None`
  where the type has no such form.
- `ProcessImage`: a `BTreeMap` keyed by (common address, IOA), so `points(common)` lists one
  station in address order. `add_point` registers a point; `update` sets its value at a time;
  `value` and `pop_event` read the image and the queue.
- The queue holds spontaneous single-object ASDUs. Each change queues one; an unchanged value
  queues nothing. Overflow drops the oldest queued ASDU and counts it (`dropped()`).
- `ProcessError`: typed refusals (global address, duplicate or unknown point, kind mismatch, no time
  tag, profile error, cause). The types of the queued ASDUs are validated against the 104 profile
  (monitor direction) by `validate_type` at registration and by `validate_profile` in the tests.

## Decisions

- **Scope: the ten monitoring types with a point value.** Protection events (M_EP_*), file transfer
  and commands are not process image values. They join the image later if S2 needs them.
- **Change means a different value or quality.** The time tag is not compared: the same value at a
  new time is not a change, so it queues nothing (tested).
- **Change detection by equality of the value.** `R32` compares bit patterns, so a NaN equal to
  itself is unchanged. The codec's types already derive equality.
- **Overflow: drop the oldest, count the drop.** The newest change must reach the controlling
  station, and the image keeps every current value, so a general interrogation recovers the state of
  a dropped event. Coalescing one pending event per point and dropping the newest were considered:
  coalescing would make the queue depend on the number of points, and dropping the newest would
  delay the state the peer most needs.
- **The initial value queues nothing.** It is the configured state, reported by a general
  interrogation (S2), not a change.
- **Time comes from the caller.** `update` takes the time of the change, so the image reads no clock
  and stays testable without one (sans I/O).
- **One object per ASDU (SQ = 0).** S2 may batch later; each event is then one object.
- **`proptest` in `igs-iec104` as a dev-dependency.** The same version is already approved and
  used by the codec for C6 (`docs/ai-log/C6.md`); no new licence or crate.

## Verification

- `cargo test -p igs-iec104 process_image`: 13 passed. Ten unit tests (registration, kind and time
  tag rules, change detection, overflow, address order, read back) and one model-based property test
  (256 random sequences of updates and pops, each compared with a model that has the same rule and
  the same queue; every queued ASDU validated against the profile).
- `cargo test --workspace --all-features`: all suites pass (the `igs-iec104` library has 19 tests).
- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`,
  `cargo deny check`: clean.

## Points for the reviewer

- The change is about 710 new lines: 340 of implementation and 370 of tests, plus four lines of
  wiring. Over the 400-line guideline. The tests are about half of it; splitting the implementation
  from its tests would still leave one commit above the guideline.
- The model in the property test applies the same drop-oldest rule as the image. It proves the
  image's bookkeeping, not that drop-oldest is the right policy; that is a decision above.
