# C2 — Information elements

## Prompt (summarised)

Task C2 of IMPLEMENTATION.md: module `elements` with one type per information
element used by the in-profile type IDs, each with `encode` and `decode` and
named flags (no raw bit masks in the public API), each citing its clause.
The element list is the set of `information_elements` of in-profile type IDs
in `profile_104.yaml`. Done when every element round-trips and the element
sizes match `element_sizes.yaml`, tested against the generated constants and
not against the YAML.

## Summary

Module layout under `crates/igs-iec104-codec/src/elements/`:

- `mod.rs`: conventions, the `unsigned_element!` macro for whole-octet
  unsigned qualifiers, the bit helpers, and the re-exports of the C1 types
  reused by the profile (`Nva` = F16, `Sva` = I16, `ShortFloat` = R32,
  `Cp16Time2a`).
- `quality.rs`: QDS, SIQ, DIQ, QDP, SEP, with `QualityFlags` (BL, SB, NT, IV)
  and `DoublePoint`.
- `measured.rs`: VTI (seven-bit two's complement, range -64..=63).
- `command.rs`: QOC, SCO, DCO, RCO, QOS.
- `system.rs`: COI, QOI, QPA, QRP, QCC, QPM, TSC.
- `status.rs`: BCR, SCD, BSI, SPE, OCI.
- `file.rs`: NOF, NOS, LOF, LOS, CHS, LSQ, SOF, FRQ, SRQ, SCQ, AFQ, Segment.
- `time.rs`: `RangeTime`, the range time of F_SC_NB_1.
- `tests.rs`: round trips, hand-written byte vectors, range rejections,
  truncated input, short destinations.

Also `crates/igs-iec104-codec/tests/elements.rs`: for each in-profile type,
the sum of the element sizes plus the time tag equals
`TypeId::object_size_bits`, both read from the generated constants.
The element table is transcribed from `profile_104.yaml` by a script.

Changes to C1 types, additive only: each of `I16`, `F16`, `R32`,
`Cp16Time2a`, `Cp24Time2a` and `Cp56Time2a` gained `pub const SIZE`.

Verification: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets --all-features -- -D warnings`, `cargo test --workspace
--all-features` (44 unit tests in the codec, 3 element size tests, 4 profile
tests) and `cargo deny check` are all green.

## Decisions

Recorded in `PROVENANCE.md`:

- D-008: the range times of F_SC_NB_1 are CP56Time2a, except that seven zero
  octets mean "unbounded" (`RangeTime::Unbounded`). The plain C1 time type
  rejects that value, so it cannot be reused directly.
- D-009: the STATUS of SOF is 0..31, because five bits cannot carry the 32
  that the text lists.

Choices that are not in the standard, recorded here:

- Reserved bits: encoders write zero, decoders ignore them. Same rule as D-007.
- Two-bit codes: DPI and the SEP event state keep all four codes apart, so
  that every value round-trips. DCS and RCS reject the codes 0 and 3, which
  the standard marks "not permitted", on decoding.
- QPM: the LPC and POP bits are not used by the standard, so they are not
  stored: written as zero, ignored on decoding.
- Segment: the element carries its length as a `Vec<u8>` and has no fixed
  `SIZE`; its length comes from LOS.
- Elements returning `Option` follow the C1 convention; the typed error of
  C3 can wrap them later.

## Points for the reviewer

- The change is about 2 100 lines, far above the 400-line guideline. Most of it
  is tests (about 540 unit lines and 126 integration lines). It was not split:
  every element module is needed for the crate to build with the module list
  in `mod.rs`.
- FBP (type 104) is not implemented: it is only used by C_TS_NA_1, which is
  outside the profile.
- TSC is part of the profile (C_TS_TA_1, 104 8.8) but missing from
  `element_sizes.yaml`. Its size and encoding (16 bits, unsigned) come from
  the profile's `information_elements` and the clause, not from that file.
- The element table in `tests/elements.rs` is a transcription of the profile
  data. A future change to the profile must update it; the test catches the
  mismatch in size, not in the names.
