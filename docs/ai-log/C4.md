# C4 — ASDU bodies

## Prompt (summarised)

Task C4 of IMPLEMENTATION.md: `Asdu` with one variant per in-profile type ID,
supporting SQ = 0 and SQ = 1 where `sq_allowed` permits. Decoding checks the
object count against the remaining length and the APDU limit. A separate
`validate_profile(&Asdu, direction)` returns which rule failed: type not in
profile, cause not in `cot_104`, cause not permitted. Type IDs outside the 104
profile decode to an `UnsupportedTypeId` error carrying the raw bytes. Done
when there is one test vector per in-profile type ID, hand-built from the
generated sizes, and tests for D-001 to D-005 through `validate_profile`.

Inputs read: `profile_104.yaml`; `101/sections/026_7.3_*` (the ASDU layouts,
including F_SG_NA_1 and F_DR_TA_1 in 7.3.6); `104/sections/024_8_*` to
`033_8.9_*` (the 104 section 8 ASDUs, including the QueryLog range times of
8.9); the 104 §5 text on the APDU length limit; and the 104 §9.5 tables
(directions).

## Summary

Module `crates/igs-iec104-codec/src/asdu/`:

- `mod.rs`: `Asdu` (cause, common address, body), `Asdu::decode`,
  `Asdu::encode`, `Asdu::to_vec`, `MAX_ASDU_LENGTH` = 249.
- `body.rs`: `Body`, one variant per in-profile type ID (54 variants, named
  as the mnemonics), generated by one `macro_rules!` from the list of
  (type ID, value) pairs. The list is taken from `profile_104.yaml`.
- `objects.rs`: `Objects<T>` in its two forms (`Individual` for SQ = 0,
  `Sequence` for SQ = 1), with the decoding loop and the object count check.
- `wire.rs`: the `Wire` trait (fixed or variable size, decode returns the
  octets it used), implemented for every element of `elements`, for tuples
  of up to four values, for `Timed<T>` (a value followed by CP56Time2a), for
  `()` (C_RD_NA_1, address only) and for `FileSegment` (F_SG_NA_1, length from
  LOS).
- `profile.rs`: `Direction`, `ProfileError`, `validate_type` and
  `validate_profile`.
- `tests.rs`: the vectors and the profile tests.

Errors: `DecodeError` gains `UnsupportedTypeId { type_code, raw }`,
`InvalidElement { element }`, `TooLong { length, max }` and
`TrailingOctets { extra }`. `EncodeError` gains `TooManyObjects`, `TooLong`
and `ValueOutOfRange`. `DecodeError` is no longer `Copy` because `raw` is a
vector.

Verification: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets --all-features -- -D warnings`, `cargo test --workspace
--all-features` (82 tests in total; 75 in the codec library, of which 20 are
ASDU tests) and `cargo deny check` are all green.

What the tests show:

- `every_in_profile_type_has_a_vector_that_round_trips`: for each of the 54
  in-profile types, a hand-built ASDU (header, address 1, sample element
  octets). The value length equals the generated object size divided by 8
  when that size is fixed. The ASDU decodes, passes `validate_profile` with
  its first allowed cause, and encodes back to the same bytes. F_DR_TA_1 uses
  SQ = 1, the only form it permits.
- D-001 (M_PS_NA_1 with causes 11 and 12), D-002 (C_BO_NA_1 accepts 8 and 9,
  C_BO_TA_1 does not accept 8), D-003 (C_CI_NA_1 with 8 and 9), D-004
  (C_CS_NA_1 with 3 is not permitted), D-005 (F_SC_NB_1 with 5). Each checks the
  error variant that `validate_profile` returns.
- Truncated and trailing octets, an ASDU over 249 octets, an invalid element
  (DCS 0 and a month-0 range time), out-of-profile type with its octets, wrong
  direction, SQ = 1 on a type that does not permit it, empty ASDU, too many
  objects, oversize encoding, short buffer, the order of the profile rules,
  and both addressing forms with round trips.

## Decisions

- D-010 (PROVENANCE.md): the largest ASDU is 249 octets. The APDU length
  field is at most 253 and counts the four control octets (104 §5).
- Element errors, the C3 open point: element decoders return `Option`. The
  wire layer maps them to `DecodeError::InvalidElement { element }` (value out
  of range) or `DecodeError::Truncated` (too few octets). One error path for
  the ASDU body, so the C3 choice is closed.
- SQ = 1 on a type that permits only SQ = 0 is decoded, then rejected by
  `validate_profile` (`SequenceNotPermitted`). The rule is a profile rule, not
  a structural one, so the decoder does not decide it.
- A type identification outside the catalogue is `UnknownTypeId` (C3). A type
  inside the catalogue but outside the profile is `UnsupportedTypeId`, with the
  whole ASDU in `raw`. `validate_profile` cannot see such a type because
  `Asdu` only holds in-profile variants; `validate_type` takes a `TypeId` from
  a header and reports `TypeNotInProfile`.
- Direction (`profile.rs`): monitor types are 1 to 44 and 70, control types
  are 45 to 69, 100 to 107 and 110 to 113, and the file transfer types 120 to
  127 are accepted in both. The source is the 104 §9.5 tables. The file
  transfer part is open: see Q-001.
- An empty SQ = 1 sequence is encoded as an empty list with no address, and
  decodes as an empty `Individual` list. That is the only case where a decoded
  and re-encoded ASDU may differ in its VSQ bit. It has no objects.
- Sizes: `Asdu::to_vec` uses a buffer of 6 + 127 × 262 octets, the largest
  ASDU that can be built, so an oversized ASDU is reported as `TooLong` and
  not as a short buffer.

## Open questions

- Q-001: are the file transfer types sent in both directions? 104 §9.5 leaves
  it to the station.
- Q-002: should a received F_SC_NB_1 with cause 5 be tolerated? D-005 leaves
  it open; the codec rejects it.

## Points for the reviewer

- Size: the module is about 880 lines of code and 610 lines of tests, far
  above the 400-line guideline. Splitting it would leave the variant list,
  the wire layer and the profile rules unable to build separately, so it
  stays in one commit.
- The variant list in `body.rs` and the sample table in `tests.rs` were
  generated from `profile_104.yaml` by a script, then reviewed. A profile change
  must update both. The vector test catches a missing or wrong type, and the
  size test catches a wrong element length.
- `Body::decode` has an arm for types outside the profile that returns
  `UnsupportedTypeId` with an empty `raw`. `Asdu::decode` checks the profile
  before calling it, so that arm is not reachable through the public API.
- Trait `Wire` is public because `Objects<T>` is public and carries the bound.
  Its methods are the layout of one value, not an extension point.
