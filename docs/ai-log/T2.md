# T2 — Client API

## Prompt (summarised)

Task T2 of IMPLEMENTATION.md: a `Client` with a connect and reconnect policy, start and stop
of the data transfer, general and counter interrogation, read, clock synchronization (never
cause 3, D-004), single, double and regulating step commands and set points with select and
execute, with and without time tags, the test command; an event stream of received ASDUs and of
the connection state; bounded channels with documented back-pressure. Done when integration
tests against the loopback server cover each procedure.

Inputs: 104 §7.1 to §7.10 (the service tables and the clock synchronization text, §7.6), §8.8
(the test command: any TSC, the answer repeats the request), the decisions D-001 to D-004 of
PROVENANCE.md.

## Summary

- `crates/igs-iec104/src/procedures.rs`: pure builders of the ASDUs of each request, returning
  `Result<Asdu, ProcedureError>`. Causes: activation (6) for every request, request (5) for a
  read. Clock synchronization is always an activation.
- `crates/igs-iec104/src/client.rs`:
  - `ClientConfig` (address, common address, reconnect policy, channel capacity, session
    parameters; the role is always controlling).
  - `ReconnectPolicy`: a delay of `initial` between attempts, doubling up to `max`, reset to
    `initial` after an established connection.
  - `Client::connect(config)`: starts a supervisor task. It connects within t0, runs the session,
    and reconnects after a drop. Dropping the client stops the supervisor.
  - `Event`: `Connected`, `Disconnected`, `ConnectFailed`, `Delivery` (an ASDU, a rejected command,
    or a change of the transfer state), `Closed`.
  - Methods for each procedure, and `send_asdu` for anything else.
- `crates/igs-iec104/src/transport.rs`: `run_shared`, which borrows the channels. `run` delegates
  to it. A client keeps its channels across the connections.
- `crates/igs-iec104/tests/client.rs`: nine integration tests against a controlled station on
  loopback that answers each procedure.

## Decisions

- **Commands while the connection is down wait** in the bounded command channel and go out on
  the next connection. The session of the new connection starts stopped, so a queued ASDU is
  rejected (`TransferStopped`) and returned as an event, not sent blindly. A `StartDt` queued
  while down is carried out on the next connection. A maintainer may prefer an immediate
  refusal while down; the change is local to `Client::request`.
- **The client does not restart the data transfer after a reconnection.** The application
  starts it again on `Event::Connected`.
- **Back-pressure.** Both channels are bounded. A caller waits when the command channel is full;
  the supervisor waits when the event channel is full. Nothing is dropped.
- **Clock synchronization** is an activation only (D-004): the builder has no spontaneous form.
- **The test command** takes its pattern from the caller (§8.8: any TSC; the answer must repeat it).
- **Errors.** The builders return `ProcedureError`; a constant that is out of range is reported,
  never a panic.

## Verification

- `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`,
  `cargo test --workspace --all-features` (204 tests: 5 unit tests of the procedures, 9 client
  integration tests, plus the earlier ones) and `cargo deny check`: green.
- Integration tests: reconnection after a drop; start and stop with their confirmations; general
  interrogation (ACTCON, ACTTERM); counter interrogation; read (the answer with cause 5); clock
  synchronization (ACTCON); test command; single command, select then execute, with a time tag;
  double, regulating step and set points (float, normalized, scaled), with and without time tags.

## Points for the reviewer

- **Size.** The change is about 950 lines (procedures 260, client 340, integration tests 330),
  above the 400-line guideline. A split for the commit: first `run_shared`, the procedures and
  their unit tests; then the client and its integration tests.
- **Not in T2:** the command-line binary (T3), the bitstring command, file transfer, parameter
  loading and the polling and cyclic procedures of §7.2 and §7.3. The plan lists none of them
  for T2.
- **The loopback station is a stub.** Its answers follow §7, but it does not check the time
  before a clock synchronization: it echoes the request.
