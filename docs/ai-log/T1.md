# T1 — Transport

## Prompt (summarised)

Task T1 of IMPLEMENTATION.md: an async driver that runs a `Session` over
`tokio::net::TcpStream`, with a connect timeout t0, the default port 2404 (§5.4),
a clean shutdown, error types, and a generic stream bound so that TLS plugs in
later. Done when tests run against an in-process loopback server with
`tokio::time::pause`.

Inputs read: 104 §5.4 (port number), and §9.6 for t0 (already read for L1). The
maintainer approved the `test-util` feature of tokio for the paused-time tests.

## Summary

- `crates/igs-iec104/src/transport.rs`:
  - `run(stream, config, commands, deliveries)`: one connection. It reads the
    stream, gives the session the bytes and the instant, writes the frames the
    session returns, forwards the ASDUs and rejections to the application, and
    shuts the stream down when the connection ends.
  - `connect(address, t0)`: TCP connect within t0; `TransportError::ConnectTimeout`
    when it expires.
  - `Transport`: the stream bound (`AsyncRead + AsyncWrite + Unpin + Send`). TCP
    now, TLS later.
  - `Command`: `SendAsdu`, `StartDt`, `StopDt`.
  - `Delivery`: `Asdu`, `Rejected`, and `Transfer(TransferState)`.
  - `DEFAULT_PORT = 2404`.
- `crates/igs-iec104/src/error.rs`: `TransportError` with `ConnectTimeout`,
  `Connect`, `Io`, `PeerClosed`, `Closed(CloseReason)`, `Encode`.
- `crates/igs-iec104/src/lib.rs`: module declarations and re-exports.
- `crates/igs-iec104/Cargo.toml`: tokio 1 (`io-util`, `macros`, `net`, `sync`,
  `time`) and, as a dev-dependency only, `test-util`. Lints as in the link crate.
- `crates/igs-iec104-link/src/lib.rs`: the crate documentation said the session
  returns a wake-up time. It returns the next deadline through `next_deadline`;
  the text is corrected.

The driver waits on three things at once: a read, a command, or the next
session deadline (`Session::next_deadline`). On a deadline it sends
`Event::Tick`. Frames split across reads and several frames in one read are
handled by the session's decoder.

## Decisions

- **Driver owns the session.** `run` creates the `Session` at the start of the
  connection. Its clock is tokio's (`tokio::time::Instant`), so a paused clock
  drives every timer in tests.
- **`Delivery::Transfer` added.** A controlling station cannot otherwise learn
  that STARTDT con arrived, so it could not wait for the transfer to start
  before sending. It is reported on each change of `Session::transfer`. T2 uses
  it.
- **Closing from the application is clean.** Dropping the command channel or the
  delivery channel ends `run` with `Ok`, after the stream is shut down. No STOPDT
  act is sent first: the standard does not require it, and a station that
  closes the connection does not wait for confirmation.
- **Errors end the connection.** A session close is `TransportError::Closed`
  with its reason; the peer closing the stream is `PeerClosed`.
- **Shutdown is best effort.** A failed shutdown after the outcome is known is
  ignored: the peer is already gone.
- **Lints as in the link crate.** `unwrap`, `expect`, indexing and unchecked
  arithmetic are denied in the crate, which reads network data; the tests are
  exempt, as in `link`. `forbid(unsafe_code)`.
- **Read buffer.** A fresh `Vec` per read. Simple and correct; a reused buffer is
  a later optimisation if the benchmark asks for one.

## Not done

- TLS (X1). The bound is ready; no TLS code is written.
- The client API, reconnection policy and general interrogation (T2).
- The t0 timeout covers the TCP connect only. The TLS handshake will need its own
  timeout in X1.

## Verification

`cargo fmt --all --check`, `cargo clippy --workspace --all-targets --all-features
-- -D warnings`, `cargo test --workspace --all-features` (187 tests: 12 new in
`igs-iec104`, one unit test and eleven integration tests) and `cargo deny check`
are all green.

Tests:

- in memory, paused clock: the t1 expiry of a start act (at 15 s), the t3 test
  (at 20 s) followed by the t1 expiry of the test (at 35 s), a confirmed test
  restarting t3 (next test at 40 s), the end of the stream after the command
  channel is dropped, the peer closing the stream, an undecodable frame, the
  transfer state reported on start, an I frame delivered to the application, and
  a command refused while stopped;
- TCP loopback, real time: a start and an ASDU across two drivers, with the
  states reported on both ends and the peer seeing the end of the stream;
- connect to a closed port: `TransportError::Connect`;
- the t0 timeout of `within_t0` with a future that never completes: at exactly
  30 s.

## Points for the reviewer

- `Delivery::Transfer` goes beyond the literal plan. It is needed for T2 to wait
  for the start of the transfer; review its placement in the public API.
- The t0 timeout is tested through `within_t0`, not through `connect`: a real
  unreachable address would make the test depend on the network.
- The Session's timers, and the rules that rest on the figures, are unchanged
  from L3 (Q-009 to Q-013).
