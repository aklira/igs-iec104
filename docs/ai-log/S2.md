# S2 — Server

## Prompt (summarised)

Task S2 of IMPLEMENTATION.md: a multi-client controlled station. End of initialization; general and
group interrogation (activation confirmation, interrogated data, activation termination); counter
interrogation; read; clock synchronization; command handling through a trait, with select-before-
operate and time-outs; negative confirmations and mirrors with causes 44 to 47; profile validation of
every received ASDU. Depends on S1 and T1. Done when the integration tests cover each procedure with
the client. Read: §7.1 to §7.10 and PROVENANCE.md. The maintainer asked for it with "commence S2";
the work stays in the working tree until a commit is requested.

## Summary

- `crates/igs-iec104/src/server/respond.rs`: the sans-I/O `Responder`. It takes one ASDU that passed
  the link, the process image, the application's `Handler`, the instant and the local time, and
  returns the ASDUs to send. Every received ASDU is checked with `validate_profile` in the control
  direction first; a violation is mirrored with cause 44 (type, direction or form) or 45 (cause).
- `crates/igs-iec104/src/server.rs`: the tokio layer. `Server::bind` checks the configuration and
  listens; `Server::run` accepts connections, and dispatches the spontaneous events of the image. Each
  connection runs `transport::run` in the controlled role and feeds its ASDUs to the `Responder`.
  `ServerHandle` publishes the points (`add_point`, `set_group`, `update`, `value`).
- `crates/igs-iec104/src/clock.rs`: the UTC conversion to CP56Time2a, moved out of the T3 binary
  (`igs104_client.rs` now calls `clock::now_utc`). Its three unit tests moved with it.
- `crates/igs-iec104/src/process_image.rs`: point groups (`set_group`, `points_in_group`) for the group
  and counter interrogations; `PointValue::body` is `pub(crate)` for the answers.
- `Handler` (trait): `select`, `execute` and, with a default that accepts, `clock_sync`. A refusal is
  `Refusal::UnknownAddress` (cause 47 mirror) or `Refusal::Rejected` (negative confirmation).
- Tests: 22 responder unit tests (no socket), 2 process-image group tests, 3 clock tests, and 17
  integration tests with the T2 `Client` over loopback (`crates/igs-iec104/tests/server.rs`).

## Decisions

- **One station address.** The server answers as its configured common address. A request to the
  global address is answered with it. The reference server did the same: its answer to
  `-c 65535 interrogate` in T3 carried its own address, 45.
- **Interrogation carries the plain types only.** The profile allows the interrogation causes (20 to
  36) for the plain monitoring types, but not for the time-tagged ones, and not for the integrated
  totals (M_IT). A point whose type does not allow the cause is left out of the answer. The data, not
  a rule of the responder, decides this: `point_answer` validates each answer with `validate_profile`.
  Counters are answered only by a counter interrogation (causes 37 to 41).
- **Groups are a set of points.** A point belongs to any of the groups 1 to 16 set with `set_group`.
  Counter groups 1 to 4 use the same membership, as the point's group. The plan does not separate them,
  and the choice is recorded here for review.
- **Counter freezing and reset are refused** with a negative activation confirmation. The image has no
  counter freezing, and the plan does not ask for it.
- **Read.** The answer carries the point's value with cause 5. An address without a point is mirrored
  with cause 47. A point whose type the profile does not allow for a request (the counters) is mirrored
  with cause 45.
- **Clock synchronization.** The confirmation carries the station's time from before the
  synchronization, as §7.6 describes, and that time is the local clock at receipt. The station keeps its
  own clock: `Handler::clock_sync` judges the request, and the default accepts it. Setting the clock is
  the application's concern.
- **Test command.** The confirmation echoes the request, which §8.8 requires: the pattern and the time
  must match the request exactly.
- **Commands: select-before-operate.** A select is kept for `selection_timeout` (default 30 s), and an
  execution is accepted only for a kept selection of the same type identification and the same address.
  A time-tagged execution therefore needs a time-tagged select. A direct execution is refused with a
  negative confirmation, and so is an execution after the time-out. A connection keeps at most 16
  selections; a select beyond them is refused. Deactivation (cause 8) is refused with a negative
  deactivation confirmation (cause 9). Commands the station does not implement (for example C_BO) are
  refused with a negative activation confirmation.
- **Negative causes.** A profile violation: the type not in the profile, its direction, or its SQ = 1
  form → 44; a cause the profile does not allow for the type → 45. A common address that is neither the
  station's nor the global one → 46. An information object address the application does not know → 47.
  The mirror repeats the request's body and the common address the peer used. Question Q-015 covers the
  form case.
- **Spontaneous events.** The dispatcher drains the image's queue into a broadcast channel, sized as the
  queue. A connection sends an event only while its data transfer is started, and only for the station's
  common address. An event that happens while the transfer is stopped is not kept for that connection; the
  controlling station recovers the state by an interrogation.
- **Lagging connections are closed.** When a connection misses events (the broadcast reports `Lagged`),
  it is closed rather than given an incomplete stream.
- **End of initialization** (M_EI, cause 4, with the configured cause of initialization) is sent once per
  connection, when its data transfer first starts. The timing is question Q-014.
- **Outgoing ASDUs wait for the window of k.** The connection keeps its answers and events in a queue; a
  rejected send returns to the front of it, and the queue is retried every 10 ms while it is not empty.
- **No new dependency.** `tokio` already has the features used (`sync` for broadcast and `Notify`, `time`,
  `net`, `macros` for `select!`). `proptest` is unchanged.

## Findings during the work

- The profile check found a defect in the first version of the interrogation: the counters were sent
  with the interrogation cause 20, which the profile does not allow for M_IT. The check is now per point
  (`point_answer`), and a unit test asserts that every answer to an interrogation or a read is a valid
  monitoring ASDU.
- A select and its execution must be of the same type. The integration test had mixed a plain select with
  a time-tagged execution; the station refused it, as the rule says. The test now uses the same form for
  both, and the rule is written in the module documentation.

## Not covered by tests

- The lag closing of a connection (`Lagged`), the closing on an unreadable clock, and the retry of a
  rejected window send. The code paths are written, but no test drives them.
- The bench. The T4 matrix and the L4/L5 scenarios are for the client and the probe; no bench scenario
  exercises the controlled station against the reference client yet. That is S5's interop gate.

## Points for the reviewer

- The change is about 2,500 new lines: the responder with its tests is 1,300 of them. Far over the
  400-line guideline. A split is possible (the clock move and the groups; then the responder; then the
  server and its integration tests), but each part would still be large.
- Open questions: Q-014 (timing of the end of initialization) and Q-015 (cause for a form violation).
- The station answers as one common address. A station with several common addresses (redundancy or
  several stations behind one connection) is outside S2.
