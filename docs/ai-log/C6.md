Task C6 of IMPLEMENTATION.md: `proptest` strategies that generate every valid
ASDU and APDU; `decode(encode(x)) == x`; decoding random bytes never panics.

## Summary

- `crates/igs-iec104-codec/Cargo.toml`: `proptest = "1.11.0"` as a
  dev-dependency of the codec crate only. The library has no new dependency.
  `Cargo.lock` gains the transitive dev-dependencies.
- `crates/igs-iec104-codec/src/proptests.rs` (test-only module, wired in
  `lib.rs` under `cfg(test)`):
  - `wire::<T>()`: a value of any `Wire` type, from random octets decoded by
    its decoder. Values the standard forbids are skipped.
  - `objects::<T>(sequence)`: individual objects (0 to 8 for a fixed-size
    value, 0 to 1 for the file segment), and a sequence when allowed.
  - `asdu()`: an ASDU of any in-profile type, with a cause from
    `cot_allowed`, the sequence form when `sq_allowed` permits it, random
    flags, originator and common address. Filtered to fit in 249 octets.
  - `apdu()`: an I, S or U frame, with sequence numbers in 0..=32767 and the
    six U functions.
  - `mutated_apdu()`: a valid frame with octets changed and the end cut off.
  - `octets()`: random octets, half of them starting with 68H.
- `asdu/body.rs`: `Body::arbitrary(type_id, sequence)`, a test-only strategy
  per variant, generated by the same macro that declares `Body`.

Properties, each with `ProptestConfig::with_cases(10_000)`:

- `asdu_round_trips`: `Asdu::decode(asdu.to_vec()) == asdu`.
- `apdu_round_trips`: `Apdu::decode(apdu.to_vec()) == apdu`.
- `generated_asdus_follow_the_profile`: each generated ASDU is accepted by
  `validate_profile` in one of the two directions.
- `random_octets_never_panic`: `Asdu::decode`, `Apdu::decode`,
  `AsduHeader::decode` and the frame decoder accept any octets without
  panicking, and every frame returned is at most 255 octets.
- `mutated_frames_never_panic`: the same for valid frames with octets changed
  or cut.
- `frames_split_anywhere_come_out_whole`: up to five APDUs, concatenated and
  cut at up to eight random points, come out of `FrameDecoder` unchanged and in
  order, and each decodes to its APDU.

One more test, `generators_reach_every_in_profile_type_and_both_forms`: it
draws 10 000 ASDUs and checks that all 54 in-profile types and both addressing
forms appear. It guards against a property that passes without ever reaching
a type.

Verification: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets --all-features -- -D warnings`, `cargo test --workspace
--all-features` (104 tests: 97 in the codec library, of which 7 are the property
tests and the coverage check; 3 element tests and 4 profile tests in the
integration tests) and `cargo deny check` are all green. The six properties run
in about 5 seconds together, the coverage check in about 4 seconds.

## Decisions

- Element values come from decoding random octets, not from field-by-field
  strategies. Every element decoder accepts all its bit patterns except the
  ones the standard forbids, so decoding random octets covers the whole value
  domain with no hand-written range.
- The round-trip properties compare values, not octets: encoders write reserved
  bits as zero, so the octets of a decoded-then-encoded value may differ from
  the input octets. The value round trip is the property the plan asks for.
- Fixed-size types come in groups of up to eight objects, and the file segment
  comes alone: eight objects of the widest profile type stay under 249 octets,
  and a segment can reach 262 octets.
- Only the type, the sequence form and the cause follow the profile in the
  generator. Flags, originator and common address are free: the profile does
  not restrict them.

## Limits of the coverage

- The generators reach every type and both forms (checked by the coverage
  test). They do not reach every value of every element by construction: the
  values are those that random octets decode to. The minimum and maximum
  values of each element are covered by the unit tests of C1 and C2, not by the
  properties.
- The property tests run the decoders on random and mutated octets. They do not
  replace the fuzzing of C7, which is a human gate.
