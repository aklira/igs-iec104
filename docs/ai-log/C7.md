## Prompt (summarised)

Task C7 of IMPLEMENTATION.md: `fuzz/` (cargo-fuzz) with the targets
`apdu_decoder` and `asdu_decode`, seeded from the C4 vectors. Gate: a
maintainer runs a 24-hour campaign with no crash. Done when each target runs
ten minutes locally without a crash.

## Approvals

- `libfuzzer-sys` (the fuzzing runtime, required by cargo-fuzz): approved by
  the maintainer before it was added.
- `NCSA` licence: `libfuzzer-sys` is licensed `(MIT OR Apache-2.0) AND NCSA`.
  The NCSA part comes from the compiler-rt code it embeds. The maintainer
  approved adding NCSA to the allow list in `deny.toml`, with a comment that
  limits it to the fuzzing tool: it is never shipped, and no library crate
  depends on it.

## Summary

- `fuzz/` is its own Cargo workspace (`[workspace]` table), so the root
  workspace and its standard gate do not build it. It depends on
  `igs-iec104-codec` by path. `Cargo.toml` declares `license = "Apache-2.0"`
  for the fuzz crate itself.
- `fuzz/fuzz_targets/apdu_decoder.rs`: feeds the input to `Apdu::decode` and to
  `FrameDecoder`. Every frame that decodes must encode again and decode to the
  same value.
- `fuzz/fuzz_targets/asdu_decode.rs`: feeds the input to `Asdu::decode`, runs
  `validate_profile` in both directions, then checks that an ASDU that decodes
  encodes again and decodes to the same value.
- `fuzz/seeds/<target>/`: the seed corpus, versioned. Nine ASDUs (C_IC_NA_1,
  M_SP_TB_1, a three-value M_ME_NA_1 sequence, C_SC_NA_1, C_CS_NA_1,
  F_SG_NA_1, F_DR_TA_1, C_RD_NA_1, and an out-of-profile type 2) and seven
  frames (I, S, the U functions, the maximal I frame, and a bad start octet).
  All are hand-built octets taken from the C4 and C5 vectors.
- `fuzz/.gitignore` (written by `cargo fuzz init`) ignores `corpus/`,
  `artifacts/`, `target/` and `coverage/`. The generated corpus and any crash
  stay local.
- `fuzz/Cargo.lock` is versioned, for reproducible builds of the harness.
- `deny.toml`: `NCSA` added to the allow list, with the scope comment above.

## How to run

The first corpus directory receives the new inputs; the seeds directory is only
read. Run from the repository root:

```bash
cargo +nightly fuzz run apdu_decoder fuzz/corpus/apdu_decoder fuzz/seeds/apdu_decoder -- -max_total_time=600
```

```bash
cargo +nightly fuzz run asdu_decode fuzz/corpus/asdu_decode fuzz/seeds/asdu_decode -- -max_total_time=600
```

The gate runs the same commands with `-max_total_time=86400`, one target after
the other, or on two machines. A crash is written to `fuzz/artifacts/<target>/`.
Reproduce it with `cargo +nightly fuzz run <target> fuzz/artifacts/<target>/<file>`,
fix the bug, add a regression test to the codec, and record the finding in this
file.

## Limits

- Two targets only: the codec decoders. The link, transport and server code do
  not exist yet; their fuzz targets come with them.
- The round-trip assertions are an oracle: a failing assertion is a bug in the
  codec, not in the harness.
- The fuzz crate is not built by the standard gate, and CI does not run it. The
  licence check of `fuzz/` is run by hand with the project configuration:
  `cd fuzz && cargo deny --config ../deny.toml check licenses`.

## Decisions

- Seeds and generated corpus are separated, so the repository holds the seeds
  only: a corpus grows to hundreds of kilobytes in one run.
- The harness uses the nightly toolchain, which cargo-fuzz requires for its
  sanitizer. The project toolchain stays on stable (`rust-toolchain.toml`).
- Clippy on the harness runs with the stable toolchain
  (`cargo clippy --all-targets -- -D warnings` in `fuzz/`): the nightly
  toolchain installed here has no clippy component.

## Points for the reviewer

- The 24-hour campaign is the phase 1 exit criterion. It needs a maintainer and
  a machine that can run one core for a day. Until it passes, C7 stays unticked.
- Decide whether `fuzz/` should join CI (format, clippy and licence checks at
  least; the campaigns are too long for CI).
- The seed files are hand-built from the C4 and C5 vectors. A later change to
  the wire layout should update them, or the seeds stop being valid starting
  points (they still work as inputs, only less useful).
