# F3 — Code generation from the profile

## Prompt (summarised)

Task F3 of IMPLEMENTATION.md: `cargo xtask codegen` reads
`docs/spec/104/data/profile_104.yaml` and `docs/spec/5-4/data/formats.yaml`
and writes `crates/igs-iec104-codec/src/generated/profile.rs`: a `TypeId`
enum with all 67 type IDs and `in_104_profile` (spelled `in_profile` for
Rust naming), per type the mnemonic, the permitted SQ values, the object
size in bits, the time tag, and the allowed and not-permitted
cause-of-transmission sets as constants; the ASDU header sizes as
constants. The file starts with a generated-by banner citing its sources by
clause and is committed, because CI cannot regenerate it. Add `cargo xtask
codegen --check` that fails when the committed file is stale. Done when the
file compiles and tests assert 67 type IDs, 54 of them in the profile, and
that type ID 103 does not allow cause 3 (D-004).

## Summary

Files:

- `xtask/Cargo.toml`: added `serde` and `serde_yaml` (approved by the
  maintainer for this task; they are a dependency of the unpublished xtask
  only, and pass `cargo deny`).
- `xtask/src/main.rs`: CLI `cargo xtask codegen [--check]`; reads the two
  YAML files through the typed structs, validates, generates, formats the
  output with `rustfmt` and writes it (or compares on `--check`).
- `xtask/src/data.rs`: typed view of the data files plus a validation pass:
  byte order must be lsb-first, exactly 67 type IDs, SQ values within
  {0, 1}, known time tag, and `object_size_bits` equal to the sum of the
  element sizes plus the time tag size whenever it is not null.
- `xtask/src/emit.rs`: the emitter. Generated surface (all accessors are
  exhaustive `match` on the enum, no indexing and no unchecked arithmetic,
  so the denied lints of `igs-iec104-codec` stay quiet):
  `TypeId` (67 variants, explicit discriminants, `from_u8`, `as_u8`,
  `COUNT`, `ALL`), `TypeId::in_profile`, `mnemonic`, `sq_allowed_mask`
  (bit mask), `object_size_bits` (`Option<u16>`, `None` for the file
  transfer "Segment" type whose length varies), `time_tag` (a `TimeTag`
  enum), `cot_allowed` / `cot_not_permitted`, the `COT_ALLOWED_*` /
  `COT_NOT_PERMITTED_*` constants, and header constants (octet sizes of the
  cause of transmission, common address and information object address,
  plus `MAX_APDU_LENGTH: usize = 253`, IEC 60870-5-104 9.5).
- `crates/igs-iec104-codec/src/generated/{mod.rs, profile.rs}`: generated
  output, committed; banners cite the sources.
- `crates/igs-iec104-codec/src/lib.rs`: wires `pub mod generated;`.
- `crates/igs-iec104-codec/tests/profile.rs`: the done-criteria tests (67
  entries, 54 in profile, code round-trip, D-004 cause 3 rejected for the
  clock synchronisation command).

Checks passed: the four tests; `codegen --check` on fresh files; `codegen
--check` detected a stale file after a deliberate one-line edit; fmt,
clippy `-D warnings`, test and deny all green.

Review notes:

- The data file carries one contradiction-safe case: type ID 125 (Segment)
  has null object size in the profile data; the generated accessor returns
  `None` and C4 must decode it from its length fields.
- Doc comments paraphrase and cite clauses only; no standard text.
- Rust mnemonics like `M_SP_NA_1` are legal identifiers; the generated enum
  carries `#[allow(non_camel_case_types)]`.
