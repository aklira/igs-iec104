# C3 — ASDU header

## Prompt (summarised)

Task C3 of IMPLEMENTATION.md: the data unit identifier of an ASDU and the
information object address. `TypeId` comes from the generated profile.
Produce the variable structure qualifier (SQ and number of objects), the
cause of transmission (cause 0..63, P/N, test bit, originator address), the
common address (2 octets) and the information object address (3 octets).
Done when round-trip tests pass and decoding rejects truncated input with a
typed error.

Inputs read: `101/sections/025_7.2_*`, clauses 7.2.2 to 7.2.5 (variable
structure qualifier, cause of transmission, common address, information
object address), and `104/sections/039_9.5_*` (field sizes and byte order).

## Summary

- `crates/igs-iec104-codec/src/error.rs`: `DecodeError` (`Truncated` with the
  needed and available octets, `UnknownTypeId`) and `EncodeError`
  (`BufferTooSmall`). Both implement `Display` and `std::error::Error`.
  This is the first typed error of the codec.
- `crates/igs-iec104-codec/src/header.rs`:
  - `AsduHeader`: type identification, `VariableStructure`,
    `CauseOfTransmission`, `CommonAddress`. `SIZE` = 6 octets. `decode` and
    `encode` return the typed errors above.
  - `VariableStructure`: number 0..=127 and the SQ flag.
  - `CauseOfTransmission`: cause 0..=63, P/N and T flags, originator address.
  - `CommonAddress`: a `u16`, with `GLOBAL` (0xFFFF).
  - `InformationObjectAddress`: 24 bits, `SIZE` = 3.
  - `cause`: named values of 101 Table 14 (data only).
- `lib.rs`: wires `pub mod error;` and `pub mod header;`.

Layout: the field widths are fixed in the code. Compile-time assertions tie
them to the generated constants (`CAUSE_OF_TRANSMISSION_OCTS == 2`,
`COMMON_ADDRESS_OCTS == 2`, `INFO_OBJECT_ADDRESS_OCTS == 3`), so a profile
change that alters the sizes breaks the build instead of shifting octets.
The sizes are also checked by a unit test.

Byte order: the common address and the information object address are
little-endian (104 9.5, mode 1).

Verification: `cargo fmt --all --check`, `cargo clippy --workspace
--all-targets --all-features -- -D warnings`, `cargo test --workspace
--all-features` (55 unit tests in the codec, 3 element tests, 4 profile
tests) and `cargo deny check` are all green.

Tests added: two hand-written byte vectors (a single command with
activation and common address 1; a sequence with spontaneous cause, P/N, T,
originator 7 and common address 0x1234), a round trip of all 67 type IDs,
truncated input at every length below the header size, unknown type IDs (0
and 200), a short destination, field ranges, the cause values, and the
information object address round trip and truncation.

## Decisions

- A type identification outside the 67-entry catalogue is `UnknownTypeId`.
  A type that is in the catalogue but outside the 104 profile (for example
  M_SP_TA_1, type 2) decodes fine: the profile check belongs to C4
  (`validate_profile`).
- `CommonAddress` accepts every `u16`, including 0 (not used). The rule that
  an undefined common address is discarded is a profile rule for C4, not a
  codec rule.
- The header types have public fields, since every combination of their
  values is valid. Those with a range keep it private: `VariableStructure`
  and `CauseOfTransmission` check their range in `new`, and the decoder can
  only produce values in range because it masks the bits to their width.

## Points for the reviewer

- Error types: the header returns `Result` with the typed errors. The
  elements of C2 still return `Option`, as the C1 types do. C4 needs one error
  type for the whole ASDU. Either the element results are mapped into
  `DecodeError` there, or the element types move to `Result`. The choice is
  open and noted in PROGRESS.md.
- Size: `header.rs` has about 300 lines of code and about 160 lines of tests,
  and `error.rs` has about 60 lines. The code alone stays under the 400-line
  guideline.
