# X1 — TLS (IEC 62351-3)

## Prompt (summarised)

Task X1 of IMPLEMENTATION.md: a `TlsBackend` trait; a rustls backend (default feature) and an
OpenSSL backend (optional feature, for renegotiation); the configuration restricted to the TLS
versions, cipher suites and extensions that the conformance tables mark as mandatory or optional;
certificate validation; security events with the mnemonics of Annex A. Done when: loopback TLS
tests for client and server, rejection of a disallowed cipher suite, a test per security event
that can be triggered locally, and TLS scenarios in the bench. Depends on T1. The maintainer asked
for it with "start X1"; the work stays in the working tree until a commit is requested.

## Status

**Partly done.** The rustls and OpenSSL backends are both in, over the tokio transport, and the OpenSSL
backend renegotiates TLS 1.2 sessions. Not yet:

- the server side of clause 7.4.5 (the check that the peer renegotiates in time, and the event

- the TLS scenarios of the bench: the bench peers set `"tls": false`, and the reference server
  needs certificates before a TLS scenario can run;
- the security events that neither backend raises yet (see below), the CRL expiry of Q-026, and the
  key update and renegotiation intervals of clauses 7.4.5 and 8.4.

The plan box for X1 in IMPLEMENTATION.md §6 stays open.

## Third increment: the OpenSSL backend

Approved: the `openssl` crate 0.10.81 (Apache-2.0) and `tokio-openssl` 0.6.5 (MIT or Apache-2.0). The
system library is libssl-dev 3.5.5, which the maintainer installed.

- `crates/igs-iec104/src/tls/openssl_backend.rs` (feature `openssl`): `OpensslBackend` implements
  `TlsBackend`. TLS 1.2 and TLS 1.3, with the cipher suites, groups and signature algorithms of the
  profile written as OpenSSL names. The suites that rustls could not offer are now offered: the CBC
  suite and the DHE-RSA suite of TLS 1.2, the CCM suite of TLS 1.3, and the ffdhe2048 group. The
  station has a 2048-bit DH parameter set, so that the DHE suites exist on the server side.
- Every certificate is judged in the verify callback (`Judge`): its size (clause 6.4.2), its validity
  dates, the trust anchor at the top of the chain, and its revocation. Revocation: a CRL that the
  issuer signed (its signature checked with the issuer's key) lists the serial, and the certificate is
  refused. A certificate whose issuer has no CRL in the list is refused, as the rustls backend does.
  The callback raises the events of Annex A for the checks it makes.
- The `openssl` crate does not expose the OpenSSL error codes, so the events come from the checks the
  callback makes itself, not from the codes of the failure.
- `crates/igs-iec104/tests/tls_openssl.rs`: ten tests over sockets. TLS 1.3 and TLS 1.2 interrogations;
  a client without certificate; an unknown CA; an expired and a revoked certificate; the revoked
  certificate accepted without the CRL; an oversized certificate; the CBC, DHE and CCM suites negotiated
  by a raw OpenSSL client that offers only one suite, with their standard names checked against the
  profile; the ffdhe2048 group of TLS 1.3.
- `crates/igs-iec104/tests/fixtures/tls`: an RSA server certificate (`rsa_server.pem`), needed by the
  static RSA and DHE-RSA suites. The generator now writes it; every fixture was regenerated.

Not covered: `rsa_pss_pss_sha256` is configured but not tested, because the fixtures have no RSA-PSS
certificate. The expiry of a CRL (nextUpdate) is not checked, as in the rustls backend (Q-026).

## Fourth increment: TLS 1.2 renegotiation (OpenSSL)

Approved by the maintainer (Q-028): the lint of igs-iec104 goes from `forbid` to `deny` (the plan
forbids unsafe code in codec and link only), and one module may contain unsafe code.

- `crates/igs-iec104/src/tls/openssl_renegotiation.rs` is that module. It declares two OpenSSL
  functions: `SSL_renegotiate`, which asks for a new handshake; and `SSL_ctrl`, with the control code
  of the renegotiation counter (12, from the installed `ssl.h`). Each one is wrapped in a safe function.
- `OpensslStream` (in `openssl_backend.rs`) wraps the stream. Once the interval of the settings has
  passed, its next read or write asks for a renegotiation. A TLS 1.3 session is not renegotiated
  (clause 8.7). No renegotiation starts while a write is pending, because a retried write must see the
  same bytes. The driver does not change.
- The settings take the interval (`TlsSettings::with_renegotiation`), within 10 minutes and 24 hours
  (clause 7.4.5). The default is 12 hours. The rustls backend does not renegotiate, and says so in its
  module documentation.

Findings while implementing:

- `openssl-sys` 0.9.117 binds neither `SSL_renegotiate` nor the counter, so the declarations come from
  the installed header. The functions are in the OpenSSL 3.5.5 library that the crate links.
- The `openssl` crate does not expose the session pointer. The module takes the address of the
  `SslRef`, the convention that `foreign-types` uses for its wrappers. The counter test checks that the
  pointer is right: the count rises after a renegotiation, and the session still carries data.
- `tokio-openssl` installs its socket callbacks only while it polls. A direct `SSL_do_handshake` call
  outside a poll failed a debug assertion of that crate. The handshake is therefore driven by the next
  read or write, which is the one the stream makes.
- An idle connection is re-polled when the peer sends something. The IEC 104 test frames (t3) make the
  peer send at least every t3 when there is no traffic, so a due renegotiation starts within t3 of its
  interval.

Tests: `crates/igs-iec104/src/tls/openssl_backend/tests.rs`, two loopback tests. A TLS 1.2 session
is renegotiated on both sides after its interval, and it then carries data in both directions. A TLS 1.3
session is never renegotiated.

## Summary
- **Second increment (transport).** `tokio-rustls` 0.26 (approved by the maintainer; MIT or
  Apache-2.0; its aws-lc-rs default is left out) adapts the rustls connections to tokio streams.
  `TlsBackend` is the object-safe trait of a backend: `connect` secures an outgoing TCP connection
  for a host name, and `accept` secures an accepted one. `RustlsBackend` implements it. A failed
  handshake raises the events of Annex A, through the same mapping as the in-memory tests.
  `Secure` wraps a backend for the configurations. `ClientConfig::with_tls` and
  `ServerConfig::with_tls` select it. The transport gains `BoxedTransport`, and the errors
  `HandshakeTimeout` and `Secure`. The client secures each connection before its session. The
  server secures each accepted connection in its own task, so a slow handshake does not hold the
  accept loop. Both sides time the handshake with t0 (a decision: the standard names t0 for the
  connection establishment, and the handshake is part of it).
- `crates/igs-iec104/tests/tls.rs`: five loopback tests over real sockets: an interrogation over TLS
  with the notices of both sides; a client without a certificate is refused and the station raises
  TLS_NO_PEER_CERT; a client that proposes only suites outside the profile is refused; a TLS client
  against a plain station reports a TLS failure; a silent station is given up after t0.
- `crates/igs-iec104/examples/tls.rs`: a secured station and a secured controlling station in one
  process, with the PEM files as arguments. It stops with the reason when the connection fails or
  drops. This completes the examples of X2.

- `crates/igs-iec104/src/tls/profile.rs`: the values of the conformance tables. Cipher suites of
  TLS 1.2 (table 9) and TLS 1.3 (table 13) with their support; the groups of table 16; the
  mandatory signature algorithms of tables 17 and 18. `allows` and `allows_group` check a value
  against the tables; `is_disallowed` recognises the names of clause 7.3.
- `crates/igs-iec104/src/tls/events.rs`: the 36 security events of Annex A (21 for the handshake,
  15 for certificates), with mnemonic, severity, identifier and clause. The descriptions are ours.
  `SecurityEvents` is the trait that receives the events; `Discard` drops them.
- `crates/igs-iec104/src/tls/settings.rs`: `Identity` (certificate chain and key, in DER; the key
  is not shown by `Debug`), `TrustAnchors`, and `TlsSettings`. `validate` refuses a certificate
  size limit below 8 192 octets (clause 6.4.2). TLS 1.2 cannot be disabled (clause 10.3).
- `crates/igs-iec104/src/tls/rustls_backend.rs` (feature `rustls`, default): the provider keeps
  only the suites and groups of the tables that rustls implements. The server requires a client
  certificate (clause 6.4.3). Both verifiers are rustls's WebPKI verifiers with the CRLs; a size
  check in front of each raises `TLS_CERT_SIZE_MISMATCH`. `identity_from_pem`,
  `trust_anchors_from_pem` and `revocation_from_pem` read PEM. `raise_handshake_success` and
  `raise_handshake_failure` raise the events of a handshake. The connections are sans-I/O
  (`client_connection`, `server_connection`).
- `crates/igs-iec104/tests/fixtures/tls/generate.sh` writes the test material with the `openssl`
  command: a test root and a five-root bundle, a server and a client certificate, a client from a
  rogue root, an expired client certificate, a revoked client certificate with its CRL, and a
  server certificate of 12 832 octets (above the limit). The CA keys are not committed.
- Tests: 26 unit tests in the TLS module. Thirteen are in `tls/rustls_backend/tests.rs`, and eight of
  those run a handshake in memory, between a station's client and server connections.
- `Cargo.toml`: optional dependency `rustls` 0.23.45 with the `ring` provider (no `aws-lc-rs`,
  which needs a C build); feature `rustls` enabled by default.

## Security events

Raised and tested (8, all triggered locally): `TLS_HS_SUCCESS`, `TLS_NO_PEER_CERT`,
`TLS_NO_LOCAL_CERT`, `TLS_NO_CA_MATCH`, `TLS_CERT_EXP`, `TLS_CERT_REVOKED`,
`TLS_SESSION_CLOSED-REV`, `TLS_CERT_SIZE_MISMATCH`.

Defined, not raised yet (28): the version events (`TLS_DEPRECATED_VERSION`, `TLS_WEAK_VERSION`,
`TLS_DISALLOWED_VERSION`, `TLS_VERSION_CHANGE`: rustls has no TLS 1.0 or 1.1, so the events cannot
be triggered with it), `TLS_DISALLOWED_CIPHER` (rustls cannot offer a disallowed suite, so a
proposal can only be seen in a raw ClientHello), the renegotiation and resumption events, the
trusted-CA events, the signature and key events (`TLS_SIG_ALG_MISMATCH`, `TLS_SIG_V_FAILED`,
`TLS_SHORT_RSA_KEY`, `TLS_MIN_KEY`, `TLS_SHORT_KEY`, `TLS_DEP_HASH`, `TLS_DEP_SIG_ALGO`,
`TLS_NO-SIG_ALGO_EXT`), the CRL and OCSP events, the key update and early data events, and the
rest of the certificate events. Some need the OpenSSL backend.

## Decisions

- **rustls with the `ring` provider.** rustls's default provider, aws-lc-rs, builds a larger C library;
  `ring` needs only the C compiler that `cc` drives. Licence: `ring` is Apache-2.0 AND ISC. `cargo deny` passes; it
  reports a duplicate `windows-sys` (0.52 from `ring`, 0.61 from elsewhere) as a warning, which
  `multiple-versions = "warn"` allows.
- **The profile filters the provider.** The suites and groups that the tables do not list are
  removed (for example TLS 1.2 ChaCha20 suites, X25519). Signature schemes are not narrowed yet: the
  verification set is the provider's own, and rustls also accepts Ed25519 for certificates (not
  tested). That is a gap against "restricted to the tables".
- **The size limit is a wrapper, not a rustls setting.** rustls has no certificate size option;
  the wrapper refuses above the limit before the WebPKI check, and raises the event on the side
  that checked it.
- **Refused revoked certificates raise two events** (Q-024).
- **Events are raised by the application's handshake code.** The `raise_handshake_*` helpers map
  a rustls error to the events of Annex A. The tokio driver will call them.
- **Test material is committed, its CA keys are not.** The leaf keys in `tests/fixtures/tls` are
  test keys, never for use outside the tests. The generator regenerates everything.
- **The events that rustls cannot raise stay defined.** Their mnemonics are data; the code does not
  invent triggers.

## Approvals

1. **`tokio-rustls`**: approved by the maintainer (not in the plan's list; MIT or Apache-2.0). It is
   used in the second increment, see above.
2. **OpenSSL backend.** The plan names it for renegotiation. The `openssl` crate needs the
