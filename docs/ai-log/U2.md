# U2 — Server connection and transfer events

## Prompt (summarised)

Task U2 of IMPLEMENTATION.md (phase 6): a bounded stream of the server's connection events: a
connection opened (with its peer address and an identifier), closed (with its reason), a change of
transfer state, and a connection superseded by a switchover (§10.7). When the stream is full, the
server does not wait: it counts the events it drops. The maintainer validated the recommended API
(a stream taken once, enabled by `ServerConfig::with_events`) and asked for it with "enchaîne avec
U2". The answers to commands stay out of the stream, as recommended.

## Status

**Done in the working tree.** The box for U2 in IMPLEMENTATION.md §6 is ticked in the commit that
adds it. Phase 6 is complete with it.

## Summary

- **API.** `ServerConfig::events: Option<NonZeroUsize>` and `ServerConfig::with_events`;
  `Server::events(&mut self) -> Option<ServerEvents>`, taken once before `run`; `ServerEvents::next`
  and `ServerEvents::dropped`. `ServerEvent { Connected { id, peer }, Transfer { id, state },
  Superseded { id, by }, Closed { id, end } }` and `ConnectionEnd { Station, Transport(error),
  Forced }`. The identifier is the one the redundancy group already gave each connection.
- **Where the events come from.** `Connected` when a connection joins the group, after its TLS
  handshake when secured. `Transfer` where the connection records its state in the group.
  `Superseded`: `Group::transfer` now returns the connections a start supersedes. `Closed`: a guard
  created when the connection joins reports the end when it is dropped, with the transport's result
  at the end of `serve`, or `Forced` when the stop of U1 aborts the connection.
- **Never waiting.** The station sends with `try_send`; a full or closed stream counts the event.
  Without `with_events`, no stream exists and nothing is sent.
- **Tests.** `tests/server.rs`: a connection, its start and its end; a switchover reporting the
  superseded connection and its end; a stream of one event that nobody reads while the station
  answers an interrogation, with the drop counted; the end of a connection at a stop (`Station`).
  `src/server/tests.rs`: a connection dropped without an end is reported as `Forced`.
